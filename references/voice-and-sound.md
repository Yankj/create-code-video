# 配音、听感与结尾导演

声音身份要稳定，表达要随语义变化。稳定不等于整片同一语调；变化不等于每句换一种声音。

先按 [TTS 选型](tts-selection.md)确认供应商、运行环境和具体模型能力。讲解视频把声音当成叙事的一部分，开头、解释、转折和结尾一起导演；不是最后才给画面补一条朗读音轨。

## 先诊断，再换模型

| 现象 | 优先排查 | 处理 |
| --- | --- | --- |
| 每句话像不同的人 | 独立短句采样、参考不一致、参数变化 | 固定参考与设置，按语义段生成，保留上下文 |
| 段落忽大忽小、接头突兀 | 每段峰值归一化、裁掉气口 | 整片响度校准；检查段落连接和噪声底 |
| 聊天感不足 | 书面句式、信息密度、所有句子同重音 | 先改口语稿，区分问题/转折/解释/落句 |
| 结尾像还要说下去 | 未闭合句意、模型延续上下文 | 单独生成闭合结尾小样，要求自然落句 |
| 音乐/提示音很“廉价” | 无叙事动机、重复合成音、频率抢旁白 | 减少音效，必要时无底乐；关键动作才点声 |

不要把模型名当成改善保证。若用户要“当前最拟人且免费可用”，检索当前一手资料，并核对本环境是否真的可运行、是否需要账号/API Key、免费额度与音频使用条件。区别免费试听、限额 API 和本地开源推理；不能只按榜单推荐，也不能默认微软声音是最佳或永久免费。

## 把身份、表演、文本分开

**身份**是“谁在说”：固定音色 ID 或声音参考、语言/口音与模型设置。**表演**是“这段怎么说”：好奇、解释、转折、强调或收束。**文本**是实际念出的口语稿。使用 [声音配置样例](../examples/voice-direction.example.json)分别记录，映射到具体模型支持的接口。

有的模型接受自然语言指令，有的靠参考录音和文字标点，有的只支持有限语速/音高。供应商的导演字段、SSML、情绪标签不能混用；不支持的说明不能放进朗读文本，否则可能被念出来。参考克隆路线先选好有合适表达的参考，再用口语稿和语义段组织表演，不能给不支持 `instruct` 的模型硬传指令。

## 拟人表达先从口语稿开始

- 把长句拆成有关系的短句，像向一个人解释：先给具体观察，再说原因。保留自然的“你有没有发现”“这里有个区别”等连接，避免每句都插“其实”“对吧”或虚构笑声。
- 每句只设一个主要重音。专名首次出现给清楚读法；技术缩写不能为了口语感改掉概念。名词读法表与屏幕文案分开，确保字幕显示正确名称。
- 问句只在确实发问时上扬；陈述、转折和判断有各自落点。情绪曲线可以是好奇 → 清楚解释 → 轻强调 → 从容收束，不能整片像广告开场。
- 保留合理呼吸与思考空间，不靠堆省略号、逐字减速、全面提高音高制造“人味”。仅调整会影响当前段落的维度，避免每段重写一整套声音人格。

| 段落 | 导演目标 | 可尝试的表演说明；仅用于支持该控制的模型 |
| --- | --- | --- |
| 开头钩子 | 像对朋友提出一个有趣的问题 | 带一点好奇，首句清楚，问句轻微上扬；尽快进入主要判断，避免主持人报幕腔 |
| 机制解释 | 观众容易跟上因果 | 语速自然稳定，专有名词清楚，一个主要重音，不逐条念条目 |
| 转折纠偏 | 让区别被听见 | 转折前短暂停顿，轻强调关键差别；不突然喊话或改变声线 |
| 判断式结尾 | 让结论落定 | 最后两句完整闭合，末句从容落下，最后一个词清楚；留尾音，不拖长全部字 |
| 邀请式结尾 | 为真实的问题留空间 | 问句自然、轻轻开放，保持同一人；不强制所有结尾降调 |

这些是导演意图，不是每个 TTS 都支持的通用提示格式；具体字段见选型资源。对采用声音 ID/参考来锁定身份的模型，先试简短表演指令或空指令，再按问题增加控制。

## 小样同时包含开头和结尾

新音色给 20–40 秒左右的同稿小样，至少覆盖问题、解释、转折和收束。不能只试听一句“大家好”就锁定整片。下面是一份测试口语稿，可按题材替换；段落意图写在配置中，不念出来：

> 你有没有发现，一个 Agent 会点网页，不一定就能让人放心托付。难点在哪里？不只在执行动作，还在于它能不能观察结果、发现问题，再把问题修好。这里有个容易忽略的区别：工具用得多，不代表任务就完成了。下一次看演示，你可以留意，最后有没有真正验收。所以我更关心的，是它能不能把结果交到你手里。

比较时固定文案和听音条件，记录身份稳定、专名读法、问句、转折、末句与接头，而不是凭模型发布日期选胜者。新声音可以请用户选两个样本之一；已有选定的 Vivian 等偏好无需重复询问。只改语气问题时先沿用音色。

## 制作流程

1. **保留已选择偏好。** 如用户选 Vivian 明亮活泼女声，后续小样应沿用；其他任务仍需按其偏好选择。
2. **口语稿先行。** 句子较短，转折清楚，专有名词准备读法；不要靠标点堆叠把学术段落变聊天。
3. **生成短小样。** 按上面的完整表达曲线做样本，记录模型/版本、voice ID 或参考文件及转写、采样设置和种子。种子辅助复现，不能独自锁住音色。
4. **按语义段生成。** 用能保持身份与上下文的长度，避免每句重启；太长产生漂移则缩段。参考一致，语气可以按语义导演。替换时优先重做完整短段，保留衔接。
5. **建立稳定参考。** 使用有使用权的声音；若是合成参考，记录其来源。确保参考本身清晰、无背景音乐、转写匹配；不能用未经同意的真人样本复制身份。
6. **整片处理。** 不把每句硬裁到同样长度或各自峰值归一化；保留真实起音、尾音和气口，再处理明显噪声/频率问题、温和压缩，整片统一响度。短视频可从约 -16 LUFS / -1.5 dBTP 试起，根据平台和实听调整，不能把该数值当作通用标准。
7. **字幕对齐。** 用实际音频的 ASR/对齐工具找时间戳，回对原稿、同音字与专名。ASR 正确不证明语气好；异常重复/幻觉必须复核。
8. **混音。** 旁白优先；音乐随讲话压低或移除。不要用每镜不同的响度校准放大接缝。可用 [媒体检查](../scripts/qa_video.py) 读取响度测量。

若后处理制造金属感/呼吸抽吸，减少处理。不要用全段变速或强制改音高掩盖合成声音身份漂移。

## 开头与段落接头

开头先解决“让人想听下去”，首句自然地把观众带进具体矛盾，不用过量底乐和提示音替代钩子。起音必须完整，字幕与主视觉在语义出现时响应；不能为了抢节奏截掉第一个辅音，也不要无理由留很长黑场。

合成使用完整语义段，不按视觉页数切声音。相邻段保留语言连接与适当气口，使用同一参考/声音 ID 和稳定设置。听到接头像换人，先回到生成端重做相关完整短段，再检查整体响度；给静默做淡变不等于修好了人声。音效只对应有意义的主事件，减少或不使用底乐也是可用的混音选择。

## 结尾是单独一镜

最后两句通常承担收束：先归结论，再落到判断或行动。声线保持同一人，语义完整、重音明确，末句按意图自然下落或邀请式结束，不强制所有结尾降调。

可尝试轻微减缓末句的信息密度、保留气口，让最后一个重音有空间。先修改文字/重新合成，避免拉长每个字。结尾需要的尾音与静默保留到音轨，并让画面在最后语音后停留约 0.6–1.2 秒作为起点；以实际节奏为准。

同一个音色可生成两种结尾小样：一版判断式自然落定，一版邀请式轻轻开放，按文本意图选。问题出在末句时优先重做包含前一句的完整收束段，保持上下文；不能为了“结尾感”换一个更低沉的人。若模型持续上扬，先检查句意是否真的结束、参考是否过于兴奋、标点与支持的导演字段，再决定换路线。

记录 `audio.lastSpeechFrame` 和 `endingHoldFrames`，分镜脚本可检查结尾空间。最后 5–10 秒必须连续听看：是否突然抬调、气口被截、字幕先消失、Logo 过早退场、音乐在最后一个字撞击。

## QA 记录边界

分别记录：合成成功、ASR 文本匹配、响度测量、实际试听/用户反馈。只有真实试听才能写“听感通过”；用户评价可以作为反馈证据，不能冒充制作端已试听。

本次案例经用户反馈有效的方法是“固定参考 + 语义段 + 整体处理 + 结尾导演”，具体 Edge → Qwen 选择及参数见选型资源。它不能保证任何 TTS 超过豆包播客；比较需同稿、同听音设备和真实样本。听感未验证时如实标注，不用 ASR 准确度、响度合格或合成成功代替试听结论。
