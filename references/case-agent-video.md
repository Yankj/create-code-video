# 案例复盘：个人 Agent 对比视频

这是一个已获用户正面反馈的竖屏技术解释案例，记录可迁移方法，不分发其中的品牌图形、声音参考或私人源文件，也不把一次反馈当作通用效果评测。

## 核心 Topic

从“列举多个产品的功能差异”收束为“个人 Agent 的竞争围绕普通人能否放心托付”。五个维度变成支撑关系：使用门槛、Harness、模型、运行环境、一体化体验。

热度与技术效果分别讨论：模型进步是行业共同因素；目标管理也是默认产品体验的设计方向，不能直接断言架构代际领先；VM 是执行环境形式，不代表更高配置，OpenClaw 也可运行于宿主机或 VM。Grok Bot 的入口与场景差异可以作为传播假设，不能直接归因于模型弱或用户规模小。

## 从十四页到连续叙事

合并重复论点，按语义组织成七段；“七”只是这次内容的结果。同一张家庭旅行委托单经过提出、拆解、执行、修正、环境承载、授权体验和验收，提供持续的视觉身份。对象的变化表达内容，而非用换色卡片替代机制。

字幕预留固定区域，浅色正文加明亮关键词；屏幕空间正文与机制主视觉各司其职。官方产品标识在首次出现时辅助辨认，真实界面解释入口，示例中的个性角色按示例身份标注，不能当成统一官方吉祥物。

封面独立设计以加强缩略图命题；标题仍保留技术论证的准确性。色板与角色不成为通用默认。

## 声音问题与修正

初版逐句独立合成、变化的采样种子、按句峰值归一化，用户反馈声音身份与语气不稳定。模型换名不是充分处理。

后续使用用户选定的明亮活泼女声方向，以固定参考、相同设置和语义段合成，整片统一处理响度，依据实际音频对齐字幕，减少干扰性的电子底乐。最后单独检查语义闭合、落句与画面留白。

具体路线是：先用 Edge 在线 TTS 建立草稿；随后用 Qwen3-TTS 1.7B CustomVoice 比较 Vivian / Serena，用户选 Vivian；再用同一份合成 Vivian 参考及匹配转写，驱动 1.7B Base 的语义段合成。后段保持 `temperature=0.55`、`top_p=0.95`、`seed=18011`。Base 的参考克隆与 CustomVoice 的指令控制是两种能力，不能直接复制指令字段。完整选型理由、模型/运行版本和配置见 [TTS 选型](tts-selection.md) 与 [声音导演](voice-and-sound.md)。

用户认为该版效果不错，这是本次迭代的反馈证据。固定种子并不保证声线稳定，ASR 对稿也不证明听感。方案能否优于其他播客产品，仍需要真实同稿对照。

封面与抖音配文也是本案例已经明确的交付需求，应直接沿用。新任务的这些选项在开工时按 [发布包流程](publishing-package.md)一起确认，而不是渲染结束后才第一次提出。

## 验收经验

连续运动需要实际播放或短片段检查，播放器 `playing=true` 但 frame 不变不能算通过。原生应用控制可能卡住，因此验收工具应有超时和替代路线。联系表、结构检查、解码与响度各自证明不同事项，不互相替代。
