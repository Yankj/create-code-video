# TTS 选型与可复现配置

先判断哪条路线在当前环境真正可用，再比较同稿小样的声音。接入方便、免费、模型更新和主观自然度是四件不同的事；不维护“永远最拟人”的榜单。

## 选择顺序

1. 沿用已经明确的语言、音色、语气、预算与本地/云端偏好。用户已选的声音表现合适，就不为追新重开选择。
2. 盘点机器、可用工具和已配置服务。不要输出密钥；“文档存在”“本机能生成”“账号有额度”分别记录。
3. 新选型或用户要求“最新、最拟人、免费”时，查当前一手模型/服务文档、价格与额度，注明日期。免费试听、限额 API、本地开源推理分别说明；本地也需要下载、内存和计算时间。
4. 按中文专名读法、聊天自然度、跨段身份、开头/结尾、控制能力、耗时与实际费用，选最多两个合理候选做同稿小样。不要拿营销 demo 与自己的临时合成直接比较。
5. 新音色先给可播放小样；已有选择按既有偏好继续。选择未定时推进口语稿和视觉，不提前把整片绑死在某个供应商上。

## 路线表

以下一手资料核对于 **2026-10-11**。能力与价格会变化，制作时重查；只有下方案例路线在本项目实际生成过，其他路线是有文档依据的候选。

| 路线 | 什么时候考虑 | 控制与使用边界 |
| --- | --- | --- |
| **Qwen3-TTS 本地** | 有合适机器、希望不依赖按次收费 API，或需要稳定参考声音 | 1.7B CustomVoice 支持预设音色和指令；Base 用参考音频/转写克隆，能力不同。模型与运行环境见 [Qwen 官方仓库](https://github.com/QwenLM/Qwen3-TTS)；Apple Silicon 可评估 [MLX Audio](https://github.com/Blaizzy/mlx-audio)，其他机器按适用运行时选择。 |
| **Edge 在线 TTS / edge-tts** | 快速建立可听草稿，或当前没有适用的本地模型 | [项目说明](https://github.com/rany2/edge-tts)提供无需 API Key 的调用及语速/音量/音高设置，限制自定义 SSML。这是第三方客户端使用 Edge 在线服务，不能套用 Azure Speech 的接口、服务承诺或情绪控制，也不代表自然度最佳或永久免费。 |
| **Gemini TTS API** | 已有可用账号/额度，希望评估段落表演控制 | 当前 [语音文档](https://ai.google.dev/gemini-api/docs/speech-generation)中 3.8 系列分离朗读文本、`speech_metadata.style` 和局部语音标签；不要套用旧 Preview 提示格式。[价格页](https://ai.google.dev/gemini-api/docs/pricing)列有部分 TTS 免费档，仍需核对具体模型、资格和限额。本案例未实测。 |
| **阿里云 Model Studio TTS** | 已有服务账号，希望托管推理和声音管理 | [官方说明](https://www.alibabacloud.com/help/en/model-studio/non-realtime-tts-user-guide)有语音设计/克隆及指令控制入口，需要 API Key；按模型/地域查实际支持。不能因同属 Qwen 就照搬本地模型名、参数和声音 ID；免费额度需另查。本案例未实测。 |
| **ElevenLabs** | 用户已有可用套餐，或愿意比较其他表演路线 | [官方语音说明](https://elevenlabs.io/docs/overview/capabilities/text-to-speech)区分模型、声音设置和上下文衔接；免费档有功能限制，商业使用条件与付费计划相关。核对当前计划后再用于发布，不能把免费试听当免费商用。本案例未实测。 |

本案例中文聊天女声的优先复用路线是 Qwen 本地；这是既有机器、零 API 调用费用和用户反馈下的选择，不是对全部中文 TTS 的排名。机器不适用就重选，不能默认所有用户都有 Apple Silicon 或 CUDA。

## 这个案例实际如何选择

| 阶段 | 实际配置 | 得到的经验 |
| --- | --- | --- |
| 初版草稿 | `edge-tts`，`zh-CN-YunjianNeural`，语速 `+15%` | 接入方便、无需 API Key，因此先建立了音轨。它不是后来用户要的聊天女声，也没有做过“全供应商最自然”比较。 |
| 女声小样 | `Qwen3-TTS-12Hz-1.7B-CustomVoice`；比较 Vivian / Serena | 用户选 **Vivian，明亮活泼**。保留这项偏好；不把它变成所有项目的默认声音。 |
| 逐句版 | CustomVoice 逐句生成，随文本变化种子，按句处理峰值 | 用户反馈每段语气、音色细微变化，听起来不如期望的播客效果。更换音色名称、加电子音效不足以解决。 |
| 修正版 | `Qwen3-TTS-12Hz-1.7B-Base` + 一份合成 Vivian 参考及匹配转写；按语义段生成 | 相同参考与设置承载身份，完整段落承载表达；整片统一处理响度，对齐实际音频，减少底乐。用户反馈该版效果不错，不能把它写成客观胜过豆包。 |

原项目使用 MLX Audio。复现记录为 `mlx-audio==0.5.8`、`mlx==0.32.3`、`mlx-metal==0.32.3`；这是一套当时使用的版本，不是最新版本或跨平台安装要求。模型仓库、权重修订/量化、运行库版本也应写入具体项目，不能只记一个品牌名。

## Qwen 的两个步骤要分清

**先挑人和表演，再固定这个人。** 1.7B CustomVoice 小样用 `speaker="Vivian"` 和支持的 `instruct`，试出合适的声音参考；如果已有合适且可用的参考，就直接复用。Base 后续使用同一 `ref_audio` 与匹配 `ref_text`。参考克隆不等于可以给 Base 直接传 CustomVoice 的 `instruct`；运行库 API 也不同。

本案例 CustomVoice 小样的导演文本：

> 用轻松、自然、明亮的中文女声说话，像跟朋友聊一个有趣的科技话题。带一点笑意和好奇感，问句自然上扬，转折有短暂停顿，语速中等偏快，避免播音腔和过度夸张。

本案例 Base 修正版记录：`temperature=0.55`、`top_p=0.95`、`seed=18011`，每段保持一致。它们是尝试起点；固定种子只辅助复现，不保证同身份或跨硬件逐样本相同。按模型支持的方式实现语气，不要添加不支持的字段或把导演说明念进旁白。

官方 Python 包的 `generate_custom_voice` / `generate_voice_clone` 与 MLX 包的调用方法分开适配，读取实际版本签名。[声音配置样例](../examples/voice-direction.example.json)是项目记录格式，不是可原样发送给所有 SDK 的请求。

## 记录、缓存与交付

在项目 `VOICE.md` / `voice-config.json` 记录选择理由、已验证能力和以下内容：

- provider、具体模型及修订、运行库版本、语言、音色 ID，或参考文件 SHA-256、匹配转写与来源。
- 稳定身份设置、支持的表演字段、采样参数/种子；旁白原稿和专名读法。
- 语义段划分、开头/结尾意图、样例反馈；只有实际听过才记试听通过。
- 文本 + 模型/运行版本 + 参考校验值 + 参数作为缓存键；换参考或设置必须失效。云端无法固定模型时记录调用日期及返回信息。
- 实际音频时长、字幕对齐、整体处理参数，以及音频源文件与最终 MP4 的对应关系。

密钥不入工程。参考录音按使用权决定是否随源码分发；不便分发就给重建步骤并明确不能精确恢复同声线。TTS 源文件保留无损版本再混音编码，避免反复转码。接着按 [声音导演](voice-and-sound.md)处理拟人表达和验收。
